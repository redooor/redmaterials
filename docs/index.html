Redmaterials by Redooor

A Bootstrap 5.3 theme inspired by Google Material Design. Version 0.2.0.

Redmaterials restyles Bootstrap's components with a Material look and adds a few of its own: a navigation sidebar, corner ribbons, the ripple effect, shadow depths and wells. This site shows the components Redmaterials restyles and the ones it adds, each with a live example and the markup to copy. For Bootstrap's own defaults, see the official Bootstrap documentation.

Redmaterials is a consolidation of many works by various people; see the acknowledgements. Source code and issues are on GitHub.

Install

Copy dist/css and dist/js to your project and use redmaterials.min.css and redmaterials.min.js. Redmaterials requires Bootstrap 5.3.x and must be loaded after Bootstrap. Use Bootstrap's bundle JavaScript, which includes Popper. Neither Bootstrap 5 nor Redmaterials needs jQuery.

In your <head>:

<link href="https://fonts.googleapis.com/css?family=Roboto:300,400,500,700" rel="stylesheet">
<link href="https://fonts.googleapis.com/icon?family=Material+Icons" rel="stylesheet">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css">
<link rel="stylesheet" href="dist/css/redmaterials.min.css">

Before the closing </body>:

<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"></script>
<script src="dist/js/redmaterials.min.js"></script>

Roboto is not bundled with Redmaterials, so add the font link above (or load it with Web Font Loader). Material Icons is optional; it is used for the icons on this site.

Customising

The theme colours and sizes are Sass variables. Load the variables module with your values first, then Redmaterials, and compile with Sass (sass --load-path=path/to/redmaterials/scss theme.scss theme.css):

@use "variables" with ($brand-primary: #e91e63, $brand-secondary: #455a64);
@use "redmaterials";

Note to users

Components that Redmaterials inherits from Bootstrap are kept as close to Bootstrap as possible. The elements Redmaterials adds on top of Bootstrap (nav sidebar, corner ribbons, ripple effect, shadows, wells) are its own and may change in a future release. Contributions are welcome.

Colours

Redmaterials adds the 19 Google Material Design palette colours as background utilities, alongside Bootstrap's contextual colours and a small set of light/dark design tokens. No data attribute or JavaScript is required: the utility class alone enables a swatch.

Compared with stock Bootstrap. Stock Bootstrap has no .bg-red … .bg-blue-grey palette utilities, so those fills are absent; its contextual .bg-primary family uses Bootstrap's own colours, while Redmaterials adds the palette and maps .bg-primary to the Material brand.

Brand variables

The brand colours are Sass variables declared with !default in scss/variables.scss; they feed both the contextual utilities and Bootstrap's --bs-* theme variables. Each default is the shade of its palette colour nearest 500 that reaches AA with its label: $brand-primary is blue 700, $brand-danger red 700 and $brand-success green 800 under white labels, while $brand-info (cyan) and $brand-warning (amber) stay at 500 under black labels. Text and link colours walk the same scale: darker on a light page, lighter on a dark one.

Customising the brand

The supported customisation is Sass: load variables with your own values first, then load redmaterials, and compile with the Sass CLI.

@use "variables" with (
    $brand-primary: #e91e63,
    $brand-secondary: #455a64
);
@use "redmaterials";

Compile the file with Redmaterials' scss directory on the load path; changing a brand variable updates Bootstrap's --bs-* vars, the contextual utilities and the components that derive from them in one pass.

sass --load-path=path/to/redmaterials/scss theme.scss theme.css

Dark mode

Neutral tokens follow the data-bs-theme attribute: surfaces, text, dividers, control chrome, interaction washes and shadows switch to their dark values. Brand and palette fills such as .bg-red or .bg-primary are identity colours and stay the same in both modes. When a brand colour is used as text—.text-primary, .link-primary or a flat button—the --rdm-text-* and --rdm-pal-* tokens lift it towards white until it reaches 4.5:1 on the dark surface, with hover states that stay lighter than the base. The derived --bs-*-bg-subtle and --bs-*-border-subtle values are light-only, so Bootstrap's own dark values remain in force.

Utilities

Redmaterials extends Bootstrap's colour utilities with the 19-colour Material palette and a neutral default and muted variant for backgrounds, text and borders. No data attribute or JavaScript is required: the utility classes work on their own.

Compared with stock Bootstrap. Stock Bootstrap has no .bg-red palette family, .bg-default, .bg-muted, .border-default, .border-muted or .text-default, and does not restyle .text-muted; its contextual .text-* and .border-* utilities use Bootstrap's own colours, while Redmaterials adds the extra utilities and the Material palette.

How the script works

On every click a delegated listener finds the closest .ripple-effect, creates a <span class="ink"> if there is not one already, sizes it to the larger side of the element, places it at the pointer, forces a reflow and adds the animate class; removing and re-adding that class restarts the CSS keyframes on a rapid second click. The script has no dependencies and does not use jQuery.

Keyboard activation. There is no separate key handler: pressing Enter on a link or button (or Space on a button) dispatches a click with detail === 0 and no pointer coordinates, and the listener places the ink in the centre of the element for that case. A non-interactive element would need its own keyboard handling, so use a native <button> or <a href>.

Both behaviours auto-initialise: the file attaches its two document-level click listeners as soon as it runs, with no init() call to write. One listener handles .ripple-effect and the other handles [data-toggle=nav-sidebar-toggle] (with a data-bs-target fallback), so the ripple and the nav sidebar work as soon as the script is loaded.

Corner Ribbons

scss/ribbons.scss adds .corner-ribbon-wrapper and .corner-ribbon: the wrapper is a positioned, clipping container and the ribbon is an absolutely positioned 200px band rotated 45 degrees into a corner. Use one of the four position classes and any Bootstrap .bg-* utility plus a matching .text-* colour; .shadow is optional and uses the ribbon shadow token. No data attribute or JavaScript is needed.

The wrapper needs a positioned container with some height. .corner-ribbon-wrapper already sets position: relative; the examples also add Bootstrap's .position-relative and a sizing-only height so the ribbon has room, and the wrapper's overflow: hidden clips the band to the corner.

Wells

scss/wells.scss adds a simple content container: .well has 1.2em 1.5em padding, the translucent surface token, and no border, corner radius or shadow, so it reads as an inset panel rather than a card. .well-sm reduces the padding to 0.8em and .well-lg raises it to 2em. No data attribute or JavaScript is needed.

The surface and the blockquote border colour come from theme tokens, so a well follows the page into dark mode without a per-element theme attribute.

Compared with stock Bootstrap. Bootstrap 5 has no well component (the class is a Bootstrap 3-era name), so stock Bootstrap gives .well, .well-sm and .well-lg no styling and the blocks have no inset surface or padding; Redmaterials adds the well with 1.2em 1.5em padding and the translucent surface token, plus the .well-sm and .well-lg sizes. The markup is plain HTML and stays valid either way.

Default well

A .well groups a short heading and paragraph on the translucent surface.

Scroll lock

rdm-ui-disable-scroll is a runtime state class, not markup to author: js/redmaterials.js adds it to <body> while the nav sidebar is open and removes it when the sidebar closes, and scss/scroll.scss gives that class overflow: hidden. The page therefore cannot scroll behind the open drawer, and normal scrolling returns on dismissal.

It is documented as code only because it never appears in static markup: adding it by hand would lock the page with no sidebar to close, and the class is excluded from the live-example audit for that reason.

Compared with stock Bootstrap. Bootstrap's offcanvas implements its own body scroll lock; rdm-ui-disable-scroll is a Redmaterials addition for the nav sidebar, and stock Bootstrap has no such class.

To see it, open the live demo in the Nav Sidebar section and inspect the body element while the drawer is open.

The class in context

The script toggles the class on the body; this is the state it produces while the sidebar is open.

<body class="rdm-ui-disable-scroll">
    <!-- page content; overflow is locked while the nav sidebar is open -->
</body>
